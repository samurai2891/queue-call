# モバイルUI調査メモ（QRコード→スマホ運用前提）

## 店舗トップ（/s/test）
- 店名「テスト」と「いらっしゃいませ」が画面中央に表示
- 「空いています」バッジ表示あり
- 「現在の呼び出し番号: -」と「待ち組数: 0組」のカード
- 「予想待ち時間: 0分」の表示
- 「順番待ちに参加」と「メニューを見る」が横並び
- 言語切替は右上に小さく表示
- 画面上部に大きな余白がある（ヘッダーがないため）
- 「-」表示は意味不明
- ボタンは横並びで同じサイズ・同じ重み
- 全体的に情報が画面中央に集中し、上下に無駄な余白

## 順番待ち参加（/s/test/join）
- 「順番待ち受付」タイトル
- 来店人数: -/+ボタンと数字「2名」
- -/+ボタンが非常に小さい（約30px）、タッチターゲット不足
- 「ご要望（任意）」テキストエリア
- 「発券する」ボタン（青、フル幅）
- 戻るボタンは左上に小さな矢印
- フォーム全体がカード内に収まっている
- 人数選択のUIが貧弱（-/+のみ、直接数字タップ不可）
- 現在の待ち状況が表示されない（何組待ちか分からない）
- 画面下半分がすべて空白

## 呼び出しボード（/s/test/board/display）- 空状態
- 店名「テスト」がヘッダーに表示
- 「現在待ちはありません」のみ表示
- 画面全体が白い背景に灰色テキスト
- 空状態のデザインが貧弱（イラストなし、ブランディングなし）
- 店頭テレビに表示した場合、真っ白な画面に小さなテキストのみ
- 音声ミュートボタンが右上に小さく表示
- 待ち客がいない時のサイネージとしての価値がゼロ


## 全ページ詳細調査結果（QRコード→スマホ運用前提）

### 運用フロー想定
1. 来店客が店頭のQRコードをスマホで読み取る → StoreTop
2. 「順番待ちに並ぶ」をタップ → JoinQueue
3. 発券完了 → Ticket（待機中）
4. 店頭ボード（テレビ等）で現在の呼び出し番号を確認 → BoardDisplay
5. 自分の番号が呼ばれる → Ticket（呼び出し中）→ PIN入力で到着確認
6. 完了

### StoreTop（/s/{slug}）
- QRコード読み取り後の最初の画面。来店客の第一印象を決める
- 「Now Calling: -」は呼び出し中でない場合に「-」表示で意味不明
- 待ち組数「0組」は問題ないが、0人の時の表示が冗長
- 「順番待ちに並ぶ」ボタンは目立つが、QRコード運用なら即JoinQueueに飛ばすべきか検討
- メニュー表示ボタンは二次的なのに同じ高さ・同じ目立ち方
- ヘッダーに言語切替のみ、店名がbody中央にあるが小さい

### JoinQueue（/s/{slug}/join）
- 人数選択の+/-ボタンは14x14（56px）で良いサイズ
- しかし「備考」テキストエリアが3行もあり、スマホ画面の半分を占める
- 備考は大半の客が使わない → 折りたたみにすべき
- 「登録する」ボタンが画面下部に固定されていない → スクロールが必要な場合がある
- 待ち状況（現在何組待ち、推定待ち時間）が表示されない → 登録前に知りたい情報

### Ticket（/s/{slug}/ticket/{token}）- 待機中
- 番号表示は7xlで大きいが、「あなたの番号」ラベルが小さすぎる
- 「現在呼び出し中」と「前に待っている組数」が2カラムグリッドだが、スマホでは狭い
- 推定待ち時間の表示は良い
- 「待ち時間アラート設定」セクションが複雑 → ドロップダウンは高齢者に分かりにくい
- SMS登録セクション、PWAインストールバナー、通知設定リンクが縦に並び情報過多
- キャンセルボタンが目立ちすぎ（アウトラインだが大きい）

### Ticket（呼び出し中状態）
- 背景がsuccess/5で薄い緑 → もっと強い視覚的変化が必要
- 「あなたの番です！」メッセージは良いが、PIN入力ボタンが画面下部
- バイブレーション(200,100,200,100,200)は良い実装
- しかしスマホの画面がOFFの場合、通知が来ても気づきにくい

### BoardDisplay（/s/{slug}/board/display）
- 空状態が「現在待ちはありません」のみ → 店頭テレビに表示した場合、白い画面に小さなテキスト
- 待ち客がいる場合：呼び出し番号が6-8remで大きいのは良い
- 待ち番号グリッドは5列で最大10件表示 → 十分
- しかし呼び出し中の番号と待ち番号の視覚的差別化が弱い
- PIN表示は良いが、遠くから見えるかは疑問
- 店名が4xlだが、テレビサイズでは小さい可能性
- 混雑レベルバッジは良い機能だが小さい
- フッターの「Powered by」と接続状態は不要な情報

### KioskDisplay（/s/{slug}/kiosk/display）
- 言語選択画面は良い構造
- 人数選択の+/-ボタンは20x20（80px）で十分大きい
- 「発券する」ボタンは24（96px）高さで良い
- 成功画面の番号表示は12rem（192px）で非常に大きい
- しかし成功画面にQRコード表示がない → スマホでチケットを確認する手段がない

### Staff（/s/{slug}/staff）
- PINログイン画面にテンキーがない → inputMode="numeric"はあるがUIとして不十分
- 「次を呼ぶ」ボタンはh-16で大きいが、スクロールしないと見えない場合がある
- 手動追加フォームが常に展開 → 折りたたみにすべき
- チケットリストのアクションボタン（再呼び出し、スキップ）がsize="sm"で小さい
- ScrollAreaのh-[calc(100vh-400px)]は画面サイズによっては短すぎる

### Checkin（/s/{slug}/checkin）
- 番号入力フィールドはh-16、text-3xlで良いサイズ
- しかしこのページの存在意義が不明 → PIN入力方式があるのに別途チェックインページが必要か

### Menu（/s/{slug}/menu）
- フィード表示とリスト表示の切り替えは良い
- カテゴリフィルターのスクロールエリアは良い
- しかし写真サイズ切り替えボタンが小さい
- カテゴリ別セクション表示は実装済み

### Reservation（/s/{slug}/reservation）
- カレンダーUIは標準的
- しかしスマホでの操作性は未確認

### 共通の構造的問題
1. 全ページが「白背景にカード」の同じパターン → 視覚的単調さ
2. ヘッダーが統一されていない → 戻るボタンの位置、言語切替の位置がバラバラ
3. ボタンのタッチターゲットが一部44px未満
4. アニメーション・トランジションの欠如
5. 空状態のデザインが貧弱
6. エラー状態のガイダンス不足
