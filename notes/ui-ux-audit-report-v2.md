# Queue Call UI/UX 改善提案レポート v2

**前提:** QRコード→スマホ待ち登録の運用フロー  
**対象ユーザー:** デジタルに疎い飲食店スタッフ、来店した待ち客（高齢者・外国人含む）  
**評価基準:** SaaS企業の開発者として、商用リリースに耐えうるかを厳しく評価

---

## 1. 運用フロー全体像と現状の致命的問題

来店客の体験フローは以下の通りです。

| ステップ | 画面 | 操作 | 現状の問題 |
|---|---|---|---|
| 1 | StoreTop | QRコード読み取り後の着地 | 情報過多、CTAが不明確 |
| 2 | JoinQueue | 人数選択→登録 | 備考欄が邪魔、待ち状況が見えない |
| 3 | Ticket（待機中） | 自分の順番を確認 | 情報が詰め込みすぎ、何を見ればいいか分からない |
| 4 | BoardDisplay | 店頭テレビで番号確認 | 空状態が貧弱、視認性不足 |
| 5 | Ticket（呼び出し中） | 呼ばれたことに気づく→PIN入力 | 視覚的変化が弱い、緊急感がない |

**結論: 現状のUIは「機能は揃っているが、実際の飲食店の現場で使うと破綻する」レベルです。** 以下、画面ごとに問題点と改善案を詳述します。

---

## 2. 画面別の詳細分析と改善提案

### 2.1 StoreTop（QRコード着地ページ）

**現状の問題:**

StoreTopは来店客がQRコードを読み取った直後に表示される、最も重要な画面です。しかし現状では、「呼び出し中番号」「待ち組数」「推定待ち時間」「混雑レベル」「順番待ちに並ぶ」「メニューを見る」「PWAバナー」が同じ画面に詰め込まれており、来店客が「今すぐ何をすべきか」が3秒以内に判断できません。

特に深刻なのは、呼び出し中の番号が「-」と表示される点です。まだ誰も呼ばれていない場合に「-」を表示するのは、来店客にとって意味不明であり、「システムが壊れている」と誤解される可能性があります。

また、「順番待ちに並ぶ」と「メニューを見る」が同じサイズ・同じ視覚的重みで並んでおり、QRコード運用の主目的である「待ち登録」への誘導力が弱いです。

**改善提案:**

QRコード運用では、StoreTopの役割は「待ち登録への最短経路」です。以下のレイアウトに再設計すべきです。

```
┌─────────────────────────────┐
│  [店名] 大きく表示           │
│  [混雑レベルバッジ]          │
│                             │
│  ┌───────────────────────┐  │
│  │ 現在の待ち: 5組       │  │
│  │ 推定待ち時間: 約15分  │  │
│  └───────────────────────┘  │
│                             │
│  ╔═══════════════════════╗  │
│  ║  順番待ちに並ぶ  →    ║  │  ← 画面の50%を占める巨大CTA
│  ╚═══════════════════════╝  │
│                             │
│  [メニューを見る] (テキストリンク)│
│  [言語切替]                  │
└─────────────────────────────┘
```

重要な変更点は以下の通りです。

1. **「呼び出し中番号」の表示を削除する。** 来店客にとって「今呼ばれている番号」は登録前には不要な情報です。登録後のTicket画面で表示すれば十分です。
2. **「順番待ちに並ぶ」ボタンを画面の主役にする。** 高さ80px以上、背景色をprimary、テキストを24px以上にし、画面の視覚的重心にする。
3. **「メニューを見る」はテキストリンクに格下げする。** ボタンである必要はありません。
4. **待ち状況を簡潔に表示する。** 「5組待ち / 約15分」のように1行で表示し、登録の判断材料を提供する。

### 2.2 JoinQueue（順番待ち登録）

**現状の問題:**

人数選択UIは+/-ボタンが56pxの円形で、タッチ操作に適切なサイズです。この点は良い設計です。

しかし、以下の問題があります。

第一に、**備考欄（Textarea）が常に3行で表示されている**点です。来店客の90%以上は備考を入力しません。にもかかわらず、スマホ画面の約30%を備考欄が占有しており、「登録する」ボタンがファーストビューから押し出される場合があります。

第二に、**登録前に待ち状況が表示されない**点です。来店客は「今何組待っているか」「どのくらい待つか」を知った上で登録するかどうかを判断したいのに、その情報がJoinQueue画面にはありません。StoreTopに戻って確認する必要があり、フローが断絶しています。

第三に、**「登録する」ボタンが画面下部に固定されていない**点です。スマホの画面サイズによっては、備考欄の下にスクロールしないとボタンが見えません。

**改善提案:**

```
┌─────────────────────────────┐
│ ← 戻る          [言語切替]  │
│                             │
│  [店名]                     │
│  現在 5組待ち / 約15分      │  ← 待ち状況を表示
│                             │
│  人数を選んでください        │
│                             │
│  [-]    3名    [+]          │  ← 大きな数字表示
│                             │
│  [備考を追加 ▼] (折りたたみ) │  ← デフォルトは非表示
│                             │
│                             │
│ ╔═══════════════════════════╗│
│ ║   3名で登録する           ║│  ← 画面下部に固定
│ ╚═══════════════════════════╝│
└─────────────────────────────┘
```

1. **備考欄を折りたたみにする。** 「備考を追加」リンクをタップすると展開する方式にし、デフォルトでは非表示にする。
2. **待ち状況を画面上部に表示する。** StoreTopから遷移してきた場合でも、登録画面で改めて確認できるようにする。
3. **「登録する」ボタンを画面下部に固定する。** `position: fixed; bottom: 0;` で常に見えるようにする。ボタンテキストに人数を含める（「3名で登録する」）。
4. **人数選択をより直感的にする。** 1〜4名はプリセットボタン（大きなタイル）で選択可能にし、5名以上は+/-で調整する方式を検討する。

### 2.3 Ticket（待機中）— 最も長時間見る画面

**現状の問題:**

Ticket画面は来店客が最も長時間見続ける画面です。しかし現状では、1つの画面に以下の情報が詰め込まれています。

- ステータスバッジ
- 自分の番号（7xl）
- 現在呼び出し中の番号
- 前に待っている組数
- 推定待ち時間
- 待ち時間アラート設定（ドロップダウン）
- 人数・備考
- キャンセルボタン
- SMS登録セクション
- 通知設定リンク
- PWAインストールバナー

**これは情報設計の失敗です。** 来店客が知りたいのは「あと何組か」「あとどのくらいか」の2つだけです。それ以外の情報は、必要な人だけがアクセスできればよいのです。

特に問題なのは、**待ち時間アラート設定のドロップダウンUI**です。デジタルに疎い高齢者にとって、「5分前」「10分前」「15分前」から選ぶドロップダウンは理解困難です。そもそも「待ち時間アラート」という概念自体が分かりにくいです。

**改善提案:**

Ticket画面を「プログレスカード」として再設計します。

```
┌─────────────────────────────┐
│ ← [店名]         [言語切替] │
│                             │
│  ┌───────────────────────┐  │
│  │    あなたの番号        │  │
│  │       42              │  │  ← 画面の主役、超大きく
│  │                       │  │
│  │  ━━━━━━━━━━━━━━━━━━  │  │  ← プログレスバー
│  │  あと 3組 / 約10分    │  │  ← 最重要情報を1行で
│  │                       │  │
│  │  現在呼び出し中: #39   │  │  ← 補助情報
│  └───────────────────────┘  │
│                             │
│  [通知をONにする] (まだの場合)│
│                             │
│  ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈  │
│  [キャンセル] [SMS登録]     │  ← 二次的アクション
│  [詳細設定 ▼]               │  ← 折りたたみ
└─────────────────────────────┘
```

1. **情報の優先順位を明確にする。** 番号→残り組数→推定時間の順に視覚的重みを付ける。
2. **プログレスバーを追加する。** 「全体の中で自分がどの位置にいるか」を視覚的に表現する。待ち客が最も安心感を得られるUI要素です。
3. **二次的機能を折りたたみにする。** 待ち時間アラート、SMS登録、PWAインストールは「詳細設定」として折りたたむ。
4. **通知設定を簡素化する。** ドロップダウンではなく、「通知をONにする」1つのボタンにする。ONにすると自動的に「あと3組になったら通知」が設定される。

### 2.4 Ticket（呼び出し中）— 最も重要な瞬間

**現状の問題:**

呼び出し中の状態変化が弱すぎます。現状では以下の変化しかありません。

- 背景が `bg-success/5`（ほぼ白に近い薄緑）に変わる
- 「あなたの番です！」テキストが表示される
- ステータスバッジが「呼び出し中」に変わる
- バイブレーション（200,100,200,100,200）

**飲食店の現場を想像してください。** 来店客はスマホをポケットに入れて近くのコンビニに行っているかもしれません。スマホを見た瞬間に「呼ばれている！」と分かる必要があります。現状の薄緑背景では、待機中との違いがほぼ分かりません。

**改善提案:**

呼び出し中は画面全体を「緊急モード」に切り替えます。

```
┌─────────────────────────────┐
│ ██████████████████████████  │
│ ██                      ██  │
│ ██   🔔 お呼び出し中    ██  │  ← 画面全体が緑/オレンジに
│ ██                      ██  │     パルスアニメーション
│ ██      番号 42         ██  │
│ ██                      ██  │
│ ██  お店にお戻りください  ██  │
│ ██                      ██  │
│ ██ ╔═══════════════════╗██  │
│ ██ ║ 到着確認(PIN入力) ║██  │  ← 巨大ボタン
│ ██ ╚═══════════════════╝██  │
│ ██                      ██  │
│ ██  期限: 14:35まで     ██  │
│ ██████████████████████████  │
└─────────────────────────────┘
```

1. **背景色を強い色に変更する。** `bg-success`（濃い緑）または `bg-orange-500` で画面全体を塗りつぶす。テキストは白。
2. **パルスアニメーションを追加する。** 画面全体が緩やかに明滅するアニメーションで「呼ばれている」ことを強調する。
3. **不要な情報を全て隠す。** 呼び出し中は「番号」「到着確認ボタン」「期限」以外の情報を全て非表示にする。
4. **到着確認ボタンを画面の主役にする。** 高さ80px以上、画面幅いっぱいに表示する。
5. **音声を改善する。** 現在のビープ音（880Hz, 0.5秒）は短すぎます。3回繰り返すか、より目立つ音に変更する。

### 2.5 BoardDisplay（店頭呼び出しボード）— デジタルサイネージ

**現状の問題:**

BoardDisplayは店頭のテレビやモニターに表示するデジタルサイネージです。しかし現状のデザインは「Webアプリの1ページ」であり、「店頭に設置するサイネージ」としてのデザインが全くされていません。

**空状態の問題:** 「現在待ちはありません」という小さなテキストが白い画面の中央に表示されるだけです。店頭テレビに映した場合、来店客は「テレビが壊れている」「何も表示されていない」と思います。

**待ち客がいる場合の問題:** 呼び出し中の番号は6-8remで大きいですが、テレビの視聴距離（2-5m）を考慮すると、まだ小さい可能性があります。また、待ち番号のグリッドと呼び出し番号の視覚的差別化が弱く、「どの番号が今呼ばれているのか」が一目で分かりません。

**改善提案:**

BoardDisplayを「デジタルサイネージ」として再設計します。

```
┌─────────────────────────────────────────┐
│  [店名]                    [混雑レベル] │
│                                         │
│  ┌─────────────────────────────────┐    │
│  │        呼び出し中               │    │
│  │                                 │    │
│  │          42                     │    │  ← 画面の60%を占める
│  │                                 │    │     巨大な番号表示
│  │     PIN: 7 3 5                  │    │     背景色で強調
│  │                                 │    │
│  └─────────────────────────────────┘    │
│                                         │
│  次にお待ちの方                          │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐   │
│  │ 43 │ │ 44 │ │ 45 │ │ 46 │ │ 47 │   │
│  └────┘ └────┘ └────┘ └────┘ └────┘   │
│                                         │
│  現在 8組お待ち                          │
└─────────────────────────────────────────┘
```

**空状態の改善:**

```
┌─────────────────────────────────────────┐
│                                         │
│           [店名ロゴ]                    │
│                                         │
│     QRコードで順番待ち登録              │
│                                         │
│        [大きなQRコード]                 │
│                                         │
│     スマホで読み取ってください           │
│                                         │
│  ○ 空いています                        │
│                                         │
└─────────────────────────────────────────┘
```

1. **呼び出し中番号を画面の60%に拡大する。** フォントサイズを12-16remにし、背景色（primary or success）で強調する。
2. **空状態をQRコード表示に変更する。** 待ち客がいない時は、QRコードと「スマホで読み取ってください」を表示し、サイネージとしての価値を持たせる。
3. **呼び出し時にアニメーションを追加する。** 番号が変わった瞬間に、画面全体がフラッシュするアニメーションを入れる。
4. **フッターの不要情報を削除する。** 「Powered by」や接続状態は来店客に不要。

### 2.6 Staff（スタッフ管理画面）

**現状の問題:**

スタッフ画面は毎日最も頻繁に操作される画面です。しかし現状では、以下の問題があります。

第一に、**PINログイン画面にテンキーUIがない**点です。`inputMode="numeric"` はスマホのソフトウェアキーボードを数字モードにしますが、タブレットやPCでは通常のキーボードが表示されます。飲食店のスタッフがPCやタブレットでログインする場合、テンキーUIが必要です。

第二に、**「次を呼ぶ」ボタンが画面の中間にある**点です。スタッフが最も頻繁に押すボタンが、受付状態の切り替え、手動追加フォーム、並び替えモード切替の下にあり、スクロールしないと見えない場合があります。

第三に、**手動追加フォームが常に展開されている**点です。手動追加はキオスクが使えない場合の代替手段であり、通常運用では使いません。にもかかわらず、画面の大きな面積を占有しています。

第四に、**チケットリストのアクションボタンが小さい**点です。「再呼び出し」「スキップ」「完了」ボタンがsize="sm"で、忙しい現場でのタッチ操作には小さすぎます。

**改善提案:**

スタッフ画面を「オペレーションコンソール」として再設計します。

```
┌─────────────────────────────┐
│ [店名] [スタッフ]  [ログアウト]│
│                             │
│ ╔═══════════════════════════╗│
│ ║   次のお客様を呼ぶ (5)   ║│  ← 最上部に固定、巨大
│ ╚═══════════════════════════╝│
│                             │
│ 待ち:5 | 呼出:1 | 到着:2   │  ← コンパクトなステータスバー
│                             │
│ ┌─ 呼び出し中 ─────────────┐│
│ │ #42  3名  14:30          ││  ← 呼び出し中を最優先表示
│ │ [再呼出] [スキップ] [完了]││     大きなアクションボタン
│ └──────────────────────────┘│
│                             │
│ ┌─ 待ちリスト ─────────────┐│
│ │ #43  2名  14:32          ││
│ │ #44  4名  14:35          ││
│ │ ...                      ││
│ └──────────────────────────┘│
│                             │
│ [受付停止] [手動追加] [設定] │  ← フッターに二次的操作
└─────────────────────────────┘
```

1. **「次を呼ぶ」ボタンを画面最上部に固定する。** `position: sticky; top: 0;` で常に見えるようにする。
2. **手動追加フォームを折りたたみにする。** フッターの「手動追加」ボタンをタップすると、ボトムシートとして展開する。
3. **ステータスカードをコンパクトにする。** 3つのカード（待ち/呼出/到着）を1行のバーに統合する。
4. **アクションボタンを大きくする。** 最低48px、できれば56pxのタッチターゲットにする。
5. **呼び出し中のチケットを視覚的に強調する。** 背景色を変え、リストの最上部に固定表示する。

### 2.7 KioskDisplay（店頭キオスク）

**現状の問題:**

キオスクのUIは比較的良い設計ですが、成功画面に**QRコード表示がない**点が致命的です。キオスクで発券した来店客は、紙のチケットを受け取るわけではありません。スマホで自分のチケットを確認する手段が必要です。

**改善提案:**

成功画面にQRコードを表示し、来店客がスマホで読み取ることでTicket画面にアクセスできるようにします。

```
┌─────────────────────────────┐
│                             │
│     ✓ 受付完了              │
│                             │
│     あなたの番号             │
│        42                   │  ← 巨大表示
│                             │
│     [QRコード]              │  ← スマホで読み取り
│     スマホで読み取ると       │
│     待ち状況を確認できます    │
│                             │
│     15秒後に自動リセット     │
│                             │
└─────────────────────────────┘
```

## 3. 共通の構造的改善

### 3.1 デザインシステムの統一

現状、全ページが「白背景にshadcn/uiのカード」という同じパターンで、視覚的な単調さが深刻です。ページの役割に応じて背景色やレイアウトを変えるべきです。

| ページ種別 | 推奨背景 | 推奨レイアウト |
|---|---|---|
| 来店客向け（StoreTop, JoinQueue） | グラデーション背景 | フルスクリーン、カードなし |
| チケット表示 | 状態に応じた背景色変化 | 中央寄せ、プログレス重視 |
| 呼び出しボード | ダーク背景 | サイネージ専用レイアウト |
| スタッフ管理 | ニュートラル背景 | オペレーションコンソール |
| キオスク | ダーク or ブランドカラー背景 | タッチ最適化 |

### 3.2 タッチターゲットの統一基準

| 要素 | 現状 | 推奨最小サイズ |
|---|---|---|
| 主要CTAボタン | h-14（56px） | h-16〜h-20（64-80px） |
| 二次ボタン | size="sm"（32px） | 最低48px |
| アイコンボタン | size="icon"（40px） | 最低48px |
| 人数選択+/- | h-14（56px） | 維持（適切） |

### 3.3 アニメーションとトランジション

現状、ページ間の遷移やステータス変更にアニメーションがほぼありません。以下を追加すべきです。

1. **ページ遷移:** フェードイン（200ms）を全ページに適用
2. **ステータス変更:** 待機中→呼び出し中の切り替えに、背景色のトランジション（500ms ease）
3. **番号変更:** 呼び出しボードの番号変更時に、スケールアップ→通常サイズのアニメーション
4. **ボタン押下:** タップ時のスケールダウン（95%）フィードバック

### 3.4 空状態の改善

全ての空状態に、イラストまたはアイコン + 説明テキスト + 次のアクションへの誘導を追加します。

## 5. 設計原則のまとめ

このシステムの全てのUI設計において、以下の4原則を守るべきです。

> **3秒ルール:** どの画面でも、3秒以内に「今何をすべきか」が分かること。

> **片手操作:** 全てのタッチターゲットは48px以上。主要アクションは画面下半分に配置。

> **ゼロ学習:** 説明文を読まなくても操作できるUI。アイコン+テキストの併用。

> **現場耐性:** 騒がしい環境、濡れた手、老眼でも確実に操作可能。コントラスト比4.5:1以上。
