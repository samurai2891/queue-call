# Queue Call UI/UX 監査レポート

**作成日:** 2026年2月27日
**対象:** 全ページ（顧客向け・スタッフ向け・管理者向け）
**評価基準:** 飲食店スタッフ（デジタルに疎い層を含む）と来店客（初見・外国人を含む）の両方の使いやすさ

---

## エグゼクティブサマリー

Queue Callは機能的には十分な順番待ちシステムだが、**UI/UXの観点では「エンジニアが作ったプロトタイプ」の域を出ていない**。SaaS製品として顧客に提供するには、以下の根本的な問題を解決する必要がある。

現状の最大の問題は、**すべてのページが「白い背景に小さなカード」という同じパターンの繰り返し**であり、ページごとの役割や重要度の差が視覚的に表現されていないことである。飲食店の現場では、スタッフがレジ横のタブレットを片手で操作し、客はスマホの小さな画面で初見のシステムを使う。この文脈を無視した「デスクトップ中心のミニマルデザイン」は、実用性を著しく損なっている。

## 1. 店舗トップページ（/s/:slug）— 重大度: HIGH

### 現状の問題

店舗トップは来店客が最初に目にする画面であり、「このシステムは何か」「自分は何をすればいいか」を瞬時に伝える必要がある。しかし現状は、店名と「Welcome」の文字が中央に配置され、その下に「Now Calling」と「Groups Waiting」の2つの数値カードが並ぶだけである。

**致命的な問題点:**

| 問題 | 影響 | 重大度 |
|------|------|--------|
| 「Now Calling」の値が「-」と表示される | 初見の客は「-」が何を意味するか分からない。「システムエラー？」と誤解する | HIGH |
| 「Welcome」という英語テキストが多言語切替前に表示される | 日本語設定なのに英語が混在し、外国人向けシステムと誤解される可能性 | MED |
| 待ち状況の視覚的インジケーターが弱い | 「0組待ち」と「20組待ち」の違いが数字でしか分からない。色やプログレスバーがない | HIGH |
| 「順番待ちに参加」ボタンと「メニューを見る」ボタンが同じサイズ・同じ重み | 主要アクション（順番待ち参加）と副次アクション（メニュー閲覧）の優先度が視覚的に区別されていない | MED |
| 背景が薄いグレーのグラデーションのみ | ブランド感・店舗感がゼロ。どの店舗でも同じ見た目になる | LOW |

### 改善提案

店舗トップは「デジタルの入口看板」として再設計すべきである。来店客が3秒以内に「順番待ちに参加する」というアクションを取れるようにする。

1. **ヒーロー領域の再設計:** 画面上部60%を使い、店名を大きく表示。待ち状況は「現在の待ち組数」をプログレスリング（円形ゲージ）で視覚化し、混雑度を色で直感的に伝える（緑→黄→赤）。
2. **CTAボタンの階層化:** 「順番待ちに参加」を画面下部に固定（sticky）し、高さ64px以上の大きなボタンにする。「メニューを見る」はその上にテキストリンクとして配置。
3. **「呼び出し中」の表示改善:** 現在呼び出し中の番号がない場合は「-」ではなく、「まだ呼び出しはありません」と明示。呼び出し中の場合はアニメーション付きで目立たせる。
4. **待ち時間の目安を前面に:** 推定待ち時間が計算可能な場合、「約15分待ち」のように大きく表示する。

## 2. 順番待ち参加ページ（/s/:slug/join）— 重大度: HIGH

### 現状の問題

このページは来店客が実際に操作する最も重要なフォームだが、**「フォームを埋めてください」という事務的なUIになっている**。

**致命的な問題点:**

| 問題 | 影響 | 重大度 |
|------|------|--------|
| 人数選択の-/+ボタンが直径56px（h-14 w-14） | スマホでの片手操作では小さい。特に高齢者や手が大きい人には押しにくい | HIGH |
| 現在の待ち状況が表示されない | 「今何組待っているか」が分からないまま参加を求められる。不安感を与える | HIGH |
| 「Join Queue」というタイトルが英語的 | 翻訳されているが、UIの構造が「フォーム」であり、「これから何が起こるか」の説明がない | MED |
| Noteフィールドが大きく目立つ | 任意入力なのに3行のTextareaが目立ちすぎ。多くの客は何を書けばいいか分からない | LOW |

### 改善提案

1. **ステップ形式のUI:** 「人数を選んでください」→「確認」→「発券」の3ステップに分け、1画面1アクションにする。
2. **人数選択のタッチ最適化:** -/+ボタンを直径80px以上に拡大。または、1〜10のグリッドボタン（3×4配置）で直接タップ選択できるようにする。
3. **待ち状況の表示:** ページ上部に「現在の待ち: 5組 / 約15分」を表示し、参加の判断材料を提供する。
4. **Noteフィールドの折りたたみ:** デフォルトでは非表示にし、「備考を追加」リンクで展開する。

## 3. チケット表示ページ（/s/:slug/ticket/:token）— 重大度: MED

### 現状の問題

発券後に表示されるチケットページは情報量が多く、機能的には充実しているが、**情報の優先順位が整理されていない**。

**問題点:**

| 問題 | 影響 | 重大度 |
|------|------|--------|
| ステータスバッジ→番号→待ち情報→詳細→アクションが縦に並ぶ | 最も重要な「あなたの番号」と「あと何組」が一目で分からない | MED |
| 「待ち時間アラート設定」のUIが複雑 | Select要素で分数を選ぶUIは、初見の客には「何のための設定か」が分かりにくい | MED |
| SMS登録、通知設定、PWAインストールが同時に表示 | 情報過多。客は「順番を待つ」だけしたいのに、設定を求められる | HIGH |
| 呼び出し時のPIN入力ダイアログが3桁の個別入力 | PIN入力自体は良いが、ダイアログのサイズが小さく、テンキーが表示されない端末がある | MED |

### 改善提案

1. **チケットUIの再設計:** 画面の80%を「あなたの番号」の巨大表示に使い、その下に「あと3組」をプログレスバーで表示。その他の情報は下にスクロールで表示。
2. **通知系UIの統合:** SMS、Web Push、PWAの設定を「通知を受け取る」1つのセクションにまとめ、最もシンプルな方法（Web Push）を推奨表示。
3. **呼び出し時の全画面表示:** ステータスが「CALLED」になったら、画面全体を緑色に変え、番号とPIN入力を大きく表示。見逃しを防ぐ。

## 4. 呼び出しボード（/s/:slug/board/display）— 重大度: HIGH

### 現状の問題

呼び出しボードは店頭の大画面テレビに表示する想定だが、**現状は「大きなフォントで番号を表示するだけ」のページ**である。

**致命的な問題点:**

| 問題 | 影響 | 重大度 |
|------|------|--------|
| 待ち客がいない場合「No one waiting」のみ表示 | 大画面テレビに「No one waiting」だけ表示されるのは、店舗のブランドイメージを損なう | HIGH |
| 時計・日付の表示がない | 店頭ディスプレイとして最低限の情報が欠けている | MED |
| 待ち番号グリッドが5列固定 | 大画面テレビでは余白が多すぎ、小さな画面では窮屈 | MED |
| 背景がほぼ白 | 店頭で目立たない。デジタルサイネージとしての存在感がない | HIGH |
| 呼び出し音が単純なビープ音 | 店内の騒音に埋もれる。チャイム音やメロディの方が注意を引く | LOW |

### 改善提案

1. **デジタルサイネージとしての再設計:** 背景にダークテーマまたは店舗カラーを使い、現在呼び出し中の番号を画面の50%以上で表示。待ち番号リストは下部にスクロール表示。
2. **空状態のデザイン:** 待ち客がいない場合は、店名ロゴ・現在時刻・「いらっしゃいませ」メッセージを表示。メニュー画像のスライドショーを表示するオプションも検討。
3. **レイアウトの自動調整:** 画面サイズに応じてグリッド列数を自動調整。4K対応。
4. **呼び出しアニメーション:** 新しい番号が呼ばれたとき、画面全体がフラッシュし、番号が拡大表示されるアニメーション。

## 5. キオスクディスプレイ（/s/:slug/kiosk/display）— 重大度: HIGH

### 現状の問題

キオスクは店頭タブレットでの操作を想定しているが、**タッチ操作への最適化が不十分**である。

**致命的な問題点:**

| 問題 | 影響 | 重大度 |
|------|------|--------|
| 言語選択ボタンが縦1列・max-w-md | タブレットの横幅を活かせていない。ボタンが小さい | HIGH |
| 人数選択の-/+ボタンが直径80px | キオスクとしては十分だが、数字の直接タップ選択がない | MED |
| 発券成功画面の番号が12rem | 十分大きいが、「この番号を覚えてください」「ボードで確認してください」の案内が弱い | MED |
| 自動リセットのカウントダウンが文字のみ | 視覚的なプログレスバーがなく、あと何秒かが直感的に分からない | LOW |

### 改善提案

1. **言語選択の全画面化:** 各言語ボタンを画面の1/2〜1/3サイズにし、国旗アイコンを添える。2言語なら左右分割、3言語以上なら大きなグリッド。
2. **人数選択のグリッド化:** 1〜10の数字ボタンを大きなグリッド（2行5列）で表示。タップ1回で選択完了。
3. **発券成功画面の強化:** 番号を画面中央に超大型表示し、「この番号が呼ばれたらお越しください」のメッセージを大きく。QRコード（チケットURL）も表示して、スマホで状況確認できることを案内。
4. **自動リセットの円形プログレス:** カウントダウンを円形のプログレスバーで表示。

## 6. スタッフ管理画面（/s/:slug/staff）— 重大度: HIGH

### 現状の問題

スタッフ画面は飲食店の現場で最も頻繁に使われる画面だが、**情報密度が高すぎて、忙しい現場での瞬時の操作に適していない**。

**致命的な問題点:**

| 問題 | 影響 | 重大度 |
|------|------|--------|
| PINログイン画面にテンキーパッドがない | スマホのソフトキーボードに依存。タブレットではキーボードが画面の半分を覆う | HIGH |
| 「次を呼ぶ」ボタンが画面中央付近に配置 | 最も頻繁に使うボタンなのに、スクロールしないと見えない場合がある | HIGH |
| チケットカードのアクションボタンが小さい（size="sm"） | 忙しい現場で小さなボタンを正確にタップするのは困難 | HIGH |
| 手動追加フォームが常に表示 | 使用頻度が低い機能が画面の大部分を占め、待ちリストの視認性を下げている | MED |
| 並び替えモードのON/OFFがSwitchコンポーネント | 誤操作しやすい。モード切替は明示的なボタンの方が安全 | MED |
| ScrollAreaの高さが`calc(100vh-400px)` | 画面サイズによっては待ちリストがほとんど見えない | HIGH |

### 改善提案

1. **PINログインのテンキー化:** 0-9のテンキーパッドを画面に直接表示。PIN入力フィールドは●で表示。
2. **「次を呼ぶ」ボタンの固定:** 画面下部にsticky配置し、常にアクセス可能にする。高さ80px以上、目立つ色。
3. **チケットカードのスワイプ操作:** 左スワイプで「スキップ」、右スワイプで「完了」。ボタンは補助的に残す。
4. **手動追加フォームの折りたたみ:** デフォルトでは折りたたみ、「+手動追加」ボタンで展開。
5. **待ちリストの全画面化:** 統計カード（待ち・呼出・到着）はヘッダーに小さく表示し、リストに最大限のスペースを割り当てる。

## 11. 共通の構造的問題 — 重大度: HIGH

### 11-1. タッチターゲットの全体的な小ささ

現在のボタンサイズは多くの箇所で44px未満であり、Apple Human Interface Guidelinesの最小推奨サイズ（44×44pt）を満たしていない。飲食店の現場では、濡れた手や手袋をした状態での操作も想定すべきであり、**最低48px、理想的には56px以上**のタッチターゲットが必要である。

### 11-2. ナビゲーションの一貫性の欠如

ページによって「戻るボタン」の位置（左上）、言語切替の位置（右上）は統一されているが、**ヘッダーの高さやパディングがページごとに異なる**。StoreTopにはヘッダーがほぼなく、JoinQueueには小さなヘッダーがあり、Staffには大きなヘッダーがある。

### 11-3. 空状態・エラー状態のデザインの貧弱さ

すべてのページで、空状態は「アイコン + テキスト」、エラー状態は「赤いアイコン + テキスト」という同じパターンである。**ユーザーが次に何をすべきかのガイダンスが不足**している。

### 11-4. アニメーション・トランジションの欠如

ページ遷移、状態変化、ボタンクリック時のフィードバックがほぼない。**操作の結果が視覚的に確認できない**ため、「ボタンを押したのに反応がない」と感じる場面がある。

### 11-5. モバイルファーストの設計不足

多くのページが `max-w-md`（448px）のカードを画面中央に配置するパターンだが、**スマホの画面幅（375px〜428px）ではカードの左右に余白が少なく、タブレット（768px〜1024px）では中央に小さく表示される**。デバイスごとの最適化が不足。

## 改善の優先順位

以下の順序で改善を進めることを推奨する。

| 優先度 | 対象 | 理由 |
|--------|------|------|
| **P0** | スタッフ管理画面のタッチ最適化 | 毎日最も使われる画面。操作性が売上に直結 |
| **P0** | 呼び出しボードの再設計 | 店頭の顔。ブランドイメージに直結 |
| **P1** | 店舗トップの再設計 | 来店客の第一印象。離脱率に直結 |
| **P1** | 順番待ち参加ページのタッチ最適化 | 来店客が実際に操作する画面 |
| **P1** | キオスクのタッチ最適化 | 店頭タブレットでの操作性 |
| **P2** | チケット表示の情報整理 | 待ち中の顧客体験 |
| **P2** | 共通コンポーネントの統一 | 開発効率と一貫性 |
| **P3** | 管理者設定画面の整理 | 初期設定時のみ使用 |
| **P3** | ホームページの改善 | 直接的な業務影響は小さい |

## デザイン原則の提案

今後の改善にあたり、以下のデザイン原則を採用することを推奨する。

1. **「3秒ルール」:** どのページでも、ユーザーが3秒以内に「次に何をすべきか」を理解できること。
2. **「片手操作」:** すべてのタッチターゲットは56px以上。主要アクションは画面下部に配置。
3. **「状況認識」:** 現在の待ち状況、自分の位置、次のアクションが常に視覚的に明確であること。
4. **「ゼロ学習」:** 説明文を読まなくても操作できるUI。アイコン+テキストの併用。
5. **「現場耐性」:** 騒がしい環境、濡れた手、急いでいる状態でも確実に操作できること。
